<Aside type="note" title="TL;DR">
  Use `executionMetadata(runtime)` to read the **Workflow ID**, **Workflow Owner**, and **Execution ID** of the workflow
  that is currently running. The call returns immediately: it does not make a capability call and does not need
  consensus.
</Aside>

## Why workflow metadata is useful

Every workflow execution has an identity: which workflow is running, who owns it, and which specific run this is. Your workflow code can read that identity at runtime, which is useful when you want to:

- **Correlate logs and results** with a specific execution.
- **Add context to your own logic**, such as including the workflow ID in an error message or branching on the workflow owner.
- **Build identifiers** that are unique per workflow or per execution, such as idempotency keys.

## Available metadata

`executionMetadata()` returns a `WorkflowExecutionMetadata` object. It contains the following fields:

| Field           | Type     | Description                                                                              |
| --------------- | -------- | ---------------------------------------------------------------------------------------- |
| `workflowID`    | `string` | The unique ID of the workflow. 32 bytes, lowercase hex, **without** a `0x` prefix.       |
| `workflowOwner` | `string` | The address of the workflow's owner. 20 bytes, lowercase hex, **without** a `0x` prefix. |
| `executionID`   | `string` | The ID of the current execution. CRE generates a new one each time your workflow runs.   |

## Usage

Pass the `runtime` that the SDK gives your trigger callback to `executionMetadata()`:

```typescript
import { executionMetadata } from "@chainlink/cre-sdk"

const { workflowID, workflowOwner, executionID } = executionMetadata(runtime)
```

Unlike most `runtime` methods, `executionMetadata()` returns the object directly. There is no `.result()` to call.

## Complete example: Logging execution metadata

Here's a complete example that reads the metadata in a cron-triggered workflow and writes it to the workflow logs:

```typescript
import { CronCapability, executionMetadata, handler, Runner, type Runtime, type CronPayload } from "@chainlink/cre-sdk"

type Config = {
  schedule: string
}

type MyResult = {
  workflowID: string
  workflowOwner: string
  executionID: string
}

const onCronTrigger = (runtime: Runtime<Config>, payload: CronPayload): MyResult => {
  // Read the metadata for the current execution
  const { workflowID, workflowOwner, executionID } = executionMetadata(runtime)

  runtime.log(`Workflow ID: ${workflowID}`)
  runtime.log(`Workflow Owner: ${workflowOwner}`)
  runtime.log(`Execution ID: ${executionID}`)

  return { workflowID, workflowOwner, executionID }
}

const initWorkflow = (config: Config) => {
  const cron = new CronCapability()

  return [handler(cron.trigger({ schedule: config.schedule }), onCronTrigger)]
}

export async function main() {
  const runner = await Runner.newRunner<Config>()
  await runner.run(initWorkflow)
}
```

**What this example demonstrates:**

1. **Reading metadata**: Calls `executionMetadata(runtime)` directly in the trigger callback and destructures the three fields from the returned object.

1. **Logging**: Writes each value with `runtime.log()`, so you can find a specific execution's logs by its `executionID`.

1. **Returning metadata**: Includes the values in the workflow's result.

## Formatting the values

The `workflowID` and `workflowOwner` values are plain hex strings without a `0x` prefix. If a downstream system expects a `0x`-prefixed value, add the prefix yourself:

```typescript
const { workflowID, workflowOwner } = executionMetadata(runtime)

const prefixedWorkflowID = `0x${workflowID}`
const prefixedWorkflowOwner = `0x${workflowOwner}`
```

## Using metadata in Node Mode

`executionMetadata()` accepts the `NodeRuntime` that you receive inside [`runtime.runInNodeMode()`](/cre/reference/sdk/core#runtimeruninnodemode), so you can read the same values there:

```typescript
import { consensusIdenticalAggregation, executionMetadata, type NodeRuntime, type Runtime } from "@chainlink/cre-sdk"

const result = runtime
  .runInNodeMode((nodeRuntime: NodeRuntime<Config>): string => {
    const { executionID } = executionMetadata(nodeRuntime)

    // Use the metadata in your per-node logic, for example to build an idempotency key
    return executionID
  }, consensusIdenticalAggregation<string>())()
  .result()
```

## Things to know

- **Read the metadata fresh in each execution.** The values change between executions, so don't store them in module-level variables or reuse them across callbacks.
- **The values are read-only.** `executionMetadata()` returns a copy, so changing the returned object does not affect the runtime.
- **The Execution ID is assigned by CRE.** It is not available until your workflow is running, and you can't set it yourself.
- **Missing metadata returns empty strings.** If the environment running your workflow does not provide metadata, each field is an empty string. Check for an empty value if your logic depends on it.

<Aside type="caution" title="Don't use these values as proof of origin">
  The metadata you read in your workflow code is for your own logic. If you attach it to an outbound request, such as an
  HTTP header or body field, the recipient can't verify it, because anyone can send a request that makes the same claim.
  When a downstream system needs to know which workflow produced some data, send the data as a signed
  [report](/cre/guides/workflow/using-http-client/submitting-reports-http). A report carries the Workflow ID, Workflow
  Owner, and Execution ID as part of DON consensus, and the recipient can [verify it
  offchain](/cre/guides/workflow/using-http-client/verifying-reports-offchain).
</Aside>

## Testing your workflow

When you unit test a callback, pass `executionMetadata` in the options of `newTestRuntime()` to control the values it sees. If you don't, all fields are empty strings.

```typescript
import { describe, expect, test } from "bun:test"
import { executionMetadata } from "@chainlink/cre-sdk"
import { newTestRuntime } from "@chainlink/cre-sdk/test"

describe("executionMetadata", () => {
  test("returns the metadata set on the test runtime", () => {
    const runtime = newTestRuntime(null, {
      executionMetadata: {
        workflowID: "0020350fb4f89856a031268826d6e9b9340996637aa27859baa7b07db58bb020",
        workflowOwner: "5366890c26e8737b89d9084b4c632f7de73d1674",
        executionID: "9f38bdece8892b3452c401a7a2d5a170f078ab9b2c98c591e24028ce94b33ed2",
        donID: 0,
        donF: 0,
      },
    })

    const { workflowOwner } = executionMetadata(runtime)

    expect(workflowOwner).toBe("5366890c26e8737b89d9084b4c632f7de73d1674")
  })
})
```
