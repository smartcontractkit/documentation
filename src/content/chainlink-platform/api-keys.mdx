API keys authenticate programmatic access to Chainlink Platform products, such as the CRE CLI, the ACE APIs, and the CRE Connect API. This page describes how API key permissions work, which permissions are available for each product, and how to create and manage API keys.

## How API keys work

An API key is an organization-level credential. When you create an API key, you select the permissions the key has, and the key can act only within those permissions.

- A single API key can include permissions for multiple products. For example, one key can deploy CRE workflows and read ACE reports.
- API key permissions are a subset of all permissions. Some permissions, such as managing members or billing, are available only to organization members through their roles.
- An API key can act only within the permissions you select for it.
- You can give an API key only permissions that your own roles include. When you edit a key, you can keep permissions it already has even if your roles don't include them.

To create and manage API keys, you need a role that includes API key permissions, such as Platform User, Platform Admin, or Owner. See [RBAC](/chainlink-platform/rbac) for the full list of roles.

## Available permissions

The following tables list the permissions you can assign to an API key for each product, grouped the same way as the **API Scope** section of the creation form. Role columns show which member roles include each permission, so you can match a key's access to a role. A check mark indicates that the role includes the permission. The Owner role includes every permission for every product. For what each role is for, and for the permissions available only to members, see [RBAC](/chainlink-platform/rbac).

## Creating an API key

To create an API key:

1. Sign in to <a href="https://app.chain.link" target="_blank" rel="noopener noreferrer">app.chain.link</a>.
1. Click your account's icon in the top-right corner, then click **Org settings** in the dropdown to open the **Organization** page.
1. Click to open the **API Keys** tab and click **Create API Key**.
1. Enter a name for the key.
1. In the **API Scope** section, select the permissions for the key:
   - Each product (Platform, ACE, CRE, and CRE Connect) has its own expandable section. Expand the products the key needs access to.
   - Each product has a preset: **None**, **Read**, **All**, or **Custom**. **Read** grants the product's read permissions, **All** grants every permission available for that product, and **Custom** is applied automatically when you change any individual permission. The Chainlink Platform section offers only **None**, **Read**, and **Custom**.
   - To grant individual permissions instead of a preset, set each permission group to **None**, **Read**, or **All**. Some groups offer only a subset of these options.
1. Click **Create API Key**, then copy the key and click **Done**.

{/* prettier-ignore */}
<Aside type="caution" title="Copy your API key immediately">
  The API key is displayed only once after you create it. Copy and store it in a secure location before closing the dialog. If you lose the key, rotate it to generate a new value. See [Managing API keys](#managing-api-keys).
</Aside>

## Managing API keys

The **API Keys** tab on the Organization page lists your organization's API keys with their name, key ID, author, product access, creation date, and status. Use the **Status** and **Product access** filters or the search field to find specific keys.

Click a key's name to open its edit panel. The **Scopes** tab shows the same permission selection as the creation form: change the presets or individual permissions, then click **Save changes**. The **Actions** tab lists the operations you can perform on the key:

- **Rename API Key**: changes the key's name. The new name is visible to all organization members.
- **Rotate Key**: generates a new value for the same key. Use this when a key's value may have been exposed.
- **Delete API**: permanently deletes the API key and its value.

## API key security

- Never share your API keys. Each member should use keys with only the permissions they need.
- If a key's value may have been exposed, rotate the key from its **Actions** tab.
- Review your organization's API keys regularly and delete keys that are no longer needed.
