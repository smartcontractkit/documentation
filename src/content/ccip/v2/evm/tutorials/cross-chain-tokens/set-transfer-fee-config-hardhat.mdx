CCIP v2 token pools let pool owners opt into **pool-level token transfer fee overrides** per destination lane. When an override is disabled, the [OnRamp](https://github.com/smartcontractkit/chainlink-ccip/tree/contracts-ccip-v2.0.0/chains/evm/contracts/onRamp/OnRamp.sol) falls back to [`FeeQuoter`](https://github.com/smartcontractkit/chainlink-ccip/tree/contracts-ccip-v2.0.0/chains/evm/contracts/FeeQuoter.sol) defaults for that lane. In this tutorial you will:

1. Review the current fee configuration for both configured lanes.
2. Optionally set a fee admin who can withdraw accrued fees.
3. Configure lane-specific flat fees, transfer fees, destination gas overhead, and destination bytes overhead.
4. Send a LINK-paid transfer and inspect accrued fees in the source token pool.
5. Withdraw accrued fee tokens.
6. Disable the fee configuration on both lanes to return to `FeeQuoter` defaults.

<Aside type="note" title="Defaults apply unless you opt in">
  <ol>
    <li>
      <strong>Fee overrides are per lane:</strong> each direction is configured independently (Ethereum Sepolia →
      Arbitrum Sepolia vs. Arbitrum Sepolia → Ethereum Sepolia).
    </li>
    <li>
      <strong>FeeQuoter is the default:</strong> when <code>isEnabled: false</code> for a lane, the OnRamp uses
      FeeQuoter defaults for that lane.
    </li>
    <li>
      <strong>Faster Than Finality fees are opt-in:</strong> the <code>fastFinality*</code> fields only apply when you
      request block-depth finality (for example, <code>--extra finality=32</code>).
    </li>
  </ol>
</Aside>

## Before You Begin

<AnchoredAccordion title="Set Up Your Development Environment" number={1} depth={3}>

1. Install Node.js and npm:
   - Make sure you have `Node.js v22.10.0` or above installed. If not, install **`Node.js v22.10.0`** using the [Node.js documentation](https://nodejs.org/en/download/).
   - `npm` is bundled with Node.js. If you can't run `npm`, reinstall or update Node.js from the official installer.

2. Install/Update Chainlink `ccip-cli`:

```bash filename="Terminal"
npm install -g @chainlink/ccip-cli
ccip-cli --version
```

3. Clone the repository and navigate to the project directory:

<GitHubCard
  title="CCIP 2.0 template"
  href="https://github.com/smartcontractkit/docs-cct-hardhat"
  iconName="github-svg-card"
>
  Clone docs-cct-hardhat for the CCT Hardhat scripts used in this tutorial.
</GitHubCard>

```bash filename="Terminal"
git clone https://github.com/smartcontractkit/docs-cct-hardhat.git
cd docs-cct-hardhat
```

4. Create a `.env` file by copying the `.env.example` file, and fill in the required values:

```bash filename="Terminal"
cp .env.example .env
```

```bash filename=".env"
# Keystore name (created via `npx hardhat keystore set`)
KEYSTORE_NAME=<your_private_key_name>

# Optional: keystore name for a configured fee admin
FEE_ADMIN_KEYSTORE_NAME=your_fee_admin_keystore_name

# RPC URLs
ETHEREUM_SEPOLIA_RPC_URL=your_eth_sepolia_rpc
ARBITRUM_SEPOLIA_RPC_URL=your_arbitrum_sepolia_rpc

# Etherscan API key (required only if you pass --verify to deployment tasks)
ETHERSCAN_API_KEY=your_etherscan_api_key
```

Use the [CCIP Directory](/ccip/directory/testnet) or `helper-config.ts` to confirm the router and LINK addresses for your network.

<Aside type="tip" title="Funding">
  <ol>
    <li>Configuration and withdrawal transactions require native gas on the source chain where you broadcast.</li>
    <li>
      The <code>ccip-cli --fee-token LINK</code> examples require LINK on the source chain. You can get testnet LINK
      from the <a href="https://faucets.chain.link/">Chainlink faucet</a>.
    </li>
    <li>Token transfer examples require the sender to hold the source-chain token being transferred.</li>
  </ol>
</Aside>

<GitHubCard
  title="Complete List of Supported Chains"
  href="https://github.com/smartcontractkit/docs-cct-hardhat/blob/main/helper-config.ts"
  iconName="github-svg-card"
>
  View the complete list of supported chains in the `helper-config.ts` file.
</GitHubCard>

5. Load your environment variables:

```bash filename="Terminal"
source .env
```

6. Build the project:

```bash filename="Terminal"
npm install && npx hardhat compile
```

7. Create an encrypted Hardhat keystore, if you haven't already:

```bash filename="Terminal"
npx hardhat keystore set PRIVATE_KEY
```

Optionally, create an encrypted Hardhat keystore for the fee admin, if you haven't already:

```bash filename="Terminal"
npx hardhat keystore set FEE_ADMIN_PRIVATE_KEY
```

<Aside type="caution" title="Private key format">
  When prompted for your private key, include the <code>0x</code> prefix.
</Aside>

<Aside type="note" title="Hardhat keystore">
  <ol>
    <li>
      Hardhat prompts for a keystore password: set it on first use, or enter it to unlock on subsequent uses. Then it
      asks you to enter your private key as hidden text.
    </li>
    <li>
      The name you choose, such as <code>PRIVATE_KEY</code>, is what you set as <code>KEYSTORE_NAME</code> in{" "}
      <code>.env</code>.
    </li>
    <li>
      Use <code>npx hardhat keystore list</code> to check previously created keystores.
    </li>
  </ol>
</Aside>

<AnchoredAccordion title="Set Token Transfer Fee Configuration" number={3} depth={3}>

Use `updateTokenTransferFeeConfig` to configure fee parameters for a destination lane on the source-chain token pool.

<GitHubCard
  title="updateTokenTransferFeeConfig.ts"
  href="https://github.com/smartcontractkit/docs-cct-hardhat/blob/main/tasks/configure/fee-config/updateTokenTransferFeeConfig.ts"
  iconName="github-svg-card"
>
  View the fee config update task on GitHub.
</GitHubCard>

| Input                                       | Required | Description                                                                                                                               |
| ------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| <nobr>`--destchain`</nobr>                  | Yes      | Remote chain to configure fees for.                                                                                                       |
| Source pool env var                         | Yes      | `ETHEREUM_SEPOLIA_TOKEN_POOL`, `ARBITRUM_SEPOLIA_TOKEN_POOL`, or the `--tokenpool` override for the source chain selected by `--network`. |
| <nobr>`KEYSTORE_NAME`</nobr>                | Yes      | Hardhat keystore name for the pool owner (set in `.env`).                                                                                 |
| <nobr>`--destgasoverhead`</nobr>            | No       | Gas overhead charged in the fee model. Must be greater than `0` when enabled.                                                             |
| <nobr>`--destbytesoverhead`</nobr>          | No       | Data availability bytes overhead. Use at least `32` for Burn & Mint and Lock & Release pools.                                             |
| <nobr>`--finalityfeeusdcents`</nobr>        | No       | Flat fee in 0.01 USD units for default-finality transfers.                                                                                |
| <nobr>`--fastfinalityfeeusdcents`</nobr>    | No       | Flat fee in 0.01 USD units for fast-finality transfers.                                                                                   |
| <nobr>`--finalitytransferfeebps`</nobr>     | No       | Basis-point fee deducted from the transferred amount for default-finality transfers. Must be below `10000`.                               |
| <nobr>`--fastfinalitytransferfeebps`</nobr> | No       | Basis-point fee deducted from the transferred amount for fast-finality transfers. Must be below `10000`.                                  |
| <nobr>`--disable`</nobr>                    | No       | Set to disable the fee config for this lane.                                                                                              |
| <nobr>`--tokenpool`</nobr>                  | No       | Token pool address. Overrides the `{CHAIN}_TOKEN_POOL` env var.                                                                           |

<Aside type="note" title="Fee units: basis points vs flat fee">
  <ul>
    <li>
      <strong>Flat fee:</strong> values are in <code>0.01 USD (1 cent)</code> units. For example, <code>1</code> means
      $0.01 and <code>100</code> means $1.00.
    </li>
    <li>
      <strong>Basis points (bps):</strong> <code>1 basis points = 0.01%</code>, <code>100 basis points = 1%</code>, and{" "}
      <code>10000 basis points = 100%</code>. Values must be below <code>10000</code>.
    </li>
  </ul>
</Aside>

<Aside type="caution" title="Validation rules">
  <ol>
    <li>
      <code>--destgasoverhead</code> must be greater than <code>0</code> when the config is enabled.
    </li>
    <li>
      <code>--destbytesoverhead</code> must be at least <code>32</code> for Burn & Mint and Lock & Release pools.
    </li>
    <li>
      Basis-point fee values must be below <code>10000</code>.
    </li>
    <li>
      First-time setup should pass every fee field shown in this tutorial. Later updates can omit fields you do not want
      to change because the task defaults omitted fields to the current on-chain values.
    </li>
  </ol>
</Aside>

This section uses a **two-step update demo** for the Ethereum Sepolia → Arbitrum Sepolia lane so you can see that **omitting fields does not reset them**.

- **Step 1** sets a basis-point fee for default-finality transfers.
- **Step 2** adds a flat fee for fast-finality transfers, while intentionally omitting the basis points flag so it carries forward.

Fee behavior in this tutorial:

- **bps fields** are deducted from the transferred token amount and retained by the source pool as the pool token.
- **Flat fee fields** are charged in the selected fee token (LINK in this tutorial) and credited to the source pool.

#### Step 1: Configure a basis points fee for default-finality transfers (ETH Sepolia → Arbitrum Sepolia)

```bash filename="Terminal"
npx hardhat updateTokenTransferFeeConfig \
  --destchain arbitrumSepolia \
  --destgasoverhead 50000 \
  --destbytesoverhead 32 \
  --finalityfeeusdcents 0 \
  --finalitytransferfeebps 25 \
  --fastfinalityfeeusdcents 0 \
  --fastfinalitytransferfeebps 0 \
  --network sepolia
```

#### Step 2: Add a flat fee for fast-finality transfers (ETH Sepolia → Arbitrum Sepolia)

This command intentionally omits `--finalitytransferfeebps`. The task defaults omitted fields to the current on-chain values, so the 25 basis points default-finality fee carries forward.


#### How to read fees from the `ccip-cli` output

- The top-level `fee: <X> LINK` is the total fee paid by the sender. It is not necessarily the amount credited to the token pool.
- For the fee-token amount credited to the pool, find the receipt where `receipts[i].issuer` equals the source token pool address. The corresponding `receipts[i].feeTokenAmount` is denominated in the fee token (LINK) in wei.
- For basis points deductions, compare `tokenAmountBeforeTokenPoolFees` with the `tokens` field. Their difference is the token amount retained by the source pool.

<Aside type="caution" title="Troubleshooting">
  <ul>
    <li>
      <strong>Owner revert:</strong> confirm <code>KEYSTORE_NAME</code> is the owner of the source-chain token pool.
    </li>
    <li>
      <strong>Fee admin withdrawal revert:</strong> confirm the fee admin was set, the correct fee admin keystore is
      used, and the action is withdrawal rather than owner-only configuration.
    </li>
    <li>
      <strong>Missing gas:</strong> confirm the broadcaster has native gas on the source chain.
    </li>
    <li>
      <strong>Missing LINK:</strong> confirm the sender has source-chain LINK when using <code>--fee-token LINK</code>.
    </li>
    <li>
      <strong>Missing lane:</strong> confirm the pool lane was configured with <code>applyChainUpdates</code>.
    </li>
    <li>
      <strong>Wrong lane or pool:</strong> confirm <code>--network</code>, <code>--destchain</code>, and the source pool
      env var (or <code>--tokenpool</code>) match the intended source -> destination lane.
    </li>
    <li>
      <strong>Invalid config:</strong> confirm <code>--destgasoverhead</code> is not <code>0</code>,{" "}
      <code>--destbytesoverhead</code> is at least <code>32</code>, and basis points values are below <code>10000</code>.
    </li>
    <li>
      <strong>Fast-finality revert:</strong> confirm the pool allows block-depth finality and the requested{" "}
      <code>finality=&lt;N&gt;</code> is not below the pool minimum.
    </li>
    <li>
      <strong>No accrued fees:</strong> confirm <code>--feetokens</code> includes LINK and the source token, the send
      completed, native fee token was not used, and flat or basis points fee values are non-zero.
    </li>
  </ul>
</Aside>
