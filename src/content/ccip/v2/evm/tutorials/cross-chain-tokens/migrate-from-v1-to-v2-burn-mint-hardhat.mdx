This migration guide helps you upgrade a deployed Burn & Mint Cross-Chain Token (CCT) setup from CCIP v1 (1.5.x / 1.6.x) to CCIP v2, while keeping your existing token addresses and minimizing disruption.

<Aside type="note" title="Finality and v2 features are optional">
  <ol>
    <li>
      <strong>Default finality:</strong> Transfers use the chain's native finality unless you explicitly opt into
      block-depth faster than finality.
    </li>
    <li>
      <strong>Opt-in changes:</strong> Pool-level fees, faster than finality, and hooks only apply if you configure
      them. This guide only focuses on a safe pool migration.
    </li>
  </ol>
</Aside>

In this guide you will:

1. Confirm prerequisites and record your existing CCIP v1 deployment details.
2. Deploy new CCIP 2.0`Burn Mint` token pools on each chain.
3. Configure the v2 pools to accept messages from both the old v1 pools and the new v2 pools.
4. Cut over CCIP routing by calling [`TokenAdminRegistry`](https://github.com/smartcontractkit/chainlink-ccip/tree/contracts-ccip-v2.0.0/chains/evm/contracts/tokenAdminRegistry/TokenAdminRegistry.sol).setPool on each chain.
5. Validate transfers end-to-end, then optionally clean up legacy configuration.

## Before You Begin

<AnchoredAccordion title="Set up your development environment" number={1} depth={3}>
1. Install Node.js and npm:
   - Make sure you have `Node.js v22.10.0` or above installed. If not, install `Node.js v22.10.0` using their
     [documentation](https://nodejs.org/en/download/).
   - `npm` is bundled with Node.js. If you can't run `npm`, reinstall/update Node.js from the official installer.

2. Install/Update [Chainlink CCIP-CLI](https://docs.chain.link/ccip/tools/cli/). You can also find the [GitHub repository here](https://github.com/smartcontractkit/ccip-cli).

```bash filename="Terminal"
npm install -g @chainlink/ccip-cli
```

Verify the installation by running the following command:

```bash filename="Terminal"
ccip-cli --version
```

3. Clone the repository and navigate to the project directory:

<GitHubCard
  title="CCIP 2.0 template"
  href="https://github.com/smartcontractkit/docs-cct-hardhat"
  iconName="github-svg-card"
>
  Clone the CCIP 2.0 Hardhat template for a smoother CCT setup.
</GitHubCard>

```bash filename="Terminal"
git clone https://github.com/smartcontractkit/docs-cct-hardhat.git
cd docs-cct-hardhat
```

4. Create a `.env` file by copying the `.env.example` file, and fill in the required values:

```bash filename="Terminal"
cp .env.example .env
```

```bash filename=".env"
# Keystore name (created via `npx hardhat keystore set`)
KEYSTORE_NAME=<your_private_key_name>

# RPC URLs
ETHEREUM_SEPOLIA_RPC_URL=your_eth_sepolia_rpc
ARBITRUM_SEPOLIA_RPC_URL=your_arbitrum_sepolia_rpc

# Etherscan API key (required only if you pass --verify to deployment tasks)
ETHERSCAN_API_KEY=your_etherscan_api_key
```

<GitHubCard
  title="Complete List of Supported Chains"
  href="https://github.com/smartcontractkit/docs-cct-hardhat/blob/main/helper-config.ts"
  iconName="github-svg-card"
>
  View the complete list of supported chains in the <code>helper-config.ts</code> file.
</GitHubCard>

5. To make sure your terminal has access to these variables, run the following command:

```bash filename="Terminal"
source .env
```

6. Build the project:

```bash filename="Terminal"
npm install && npx hardhat compile
```

7. Create an encrypted Hardhat keystore, if you haven't already:

```bash filename="Terminal"
npx hardhat keystore set <your_private_key_name>
```

<Aside type="caution" title="Private key format">
  When prompted for your private key, include the <code>0x</code> prefix.
</Aside>

<Aside type="note" title="Note">
  <ol>
    <li>
      Hardhat prompts for a keystore password: set it on first use, or enter it to unlock on subsequent uses. Then it
      asks you to enter your private key as hidden text.
    </li>
    <li>
      The name you choose (e.g. <code>PRIVATE_KEY</code>) is what you set as <code>KEYSTORE_NAME</code> in{" "}
      <code>.env</code>.
    </li>
    <li>
      Use <code>npx hardhat keystore list</code> to check previously created keystores.
    </li>
  </ol>
</Aside>

</AnchoredAccordion>

<AnchoredAccordion title="What this guide assumes" number={2} depth={3}>
  - **EVM-to-EVM only**: this page is strictly for Ethereum Sepolia ↔ Arbitrum Sepolia. - **Burn & Mint pools only**:
  standard
  [`BurnMintTokenPool`](https://github.com/smartcontractkit/chainlink-ccip/tree/contracts-ccip-v2.0.0/chains/evm/contracts/pools/BurnMintTokenPool.sol)
  migrations (no custom pools). - **Admin control**: you control the `TokenAdminRegistry` administrator role for the
  token on both chains. - **Token permissions**: you can grant the required mint/burn permissions to the new v2 pools on
  each chain. - **Pool-owner actions**: you can execute pool-owner actions on both chains (for example,
  `applyChainUpdates`, `removeRemotePool`). - **Existing v1 deployment**: you are migrating an already-live CCIP v1
  setup (1.5.x or 1.6.x), not doing a new registration.
</AnchoredAccordion>

<AnchoredAccordion title="Step 8: Validate end-to-end (Sepolia → Arbitrum) with ccip-cli" number={8} depth={3}>

Send a small test transfer from Ethereum Sepolia → Arbitrum Sepolia and confirm it succeeds.

<Aside type="note" title="Prerequisites for the send">
  <ol>
    <li>You need some of your token on Ethereum Sepolia to send.</li>
    <li>You need Sepolia ETH for gas (and optionally LINK if paying fees in LINK).</li>
    <li>You need Arbitrum Sepolia ETH for gas to run any Arbitrum-side verification commands.</li>
  </ol>
</Aside>

Set the router address for Ethereum Sepolia (from the [CCIP Directory](https://docs.chain.link/ccip/directory/testnet) or `helper-config.ts` in the template):

```bash filename="Terminal"
export ETHEREUM_SEPOLIA_ROUTER=0x0BF3dE8c5D3e8A2B34D2BEeB17ABfCeBaf363A59
```

1. Send a transfer on default finality:

```bash filename="Terminal"
ccip-cli send \
  --source ethereum-testnet-sepolia \
  --router $ETHEREUM_SEPOLIA_ROUTER \
  --dest ethereum-testnet-sepolia-arbitrum-1 \
  --transfer-tokens $ETHEREUM_SEPOLIA_TOKEN=1.23 \
  --receiver 0xYourReceiverAddress \
  --wallet hardhat:$KEYSTORE_NAME \
  --rpc "$ETHEREUM_SEPOLIA_RPC_URL" \
  --rpc "$ARBITRUM_SEPOLIA_RPC_URL"
```

Your output should look something like this:

```bash filename="Terminal"
Fee: 130129888907619n = 0.000130129888907619 ETH
🚀 Sending message ... messageId => 0x4a5b6c7d8e9f0a1b2c3d4e5f60718293a4b5c6d7e8f90a1b2c3d4e5f60718293
```

2. (Optional) Request block-depth faster than finality with depth 32

Only use this if your v2 pools explicitly allow block-depth faster than finality. If this fails, omit `--extra` and retry with
default finality.

```bash filename="Terminal"
ccip-cli send \
  --source ethereum-testnet-sepolia \
  --router $ETHEREUM_SEPOLIA_ROUTER \
  --dest ethereum-testnet-sepolia-arbitrum-1 \
  --transfer-tokens $ETHEREUM_SEPOLIA_TOKEN=1.23 \
  --receiver 0xYourReceiverAddress \
  --extra finality=32 \
  --wallet hardhat:$KEYSTORE_NAME \
  --rpc "$ETHEREUM_SEPOLIA_RPC_URL" \
  --rpc "$ARBITRUM_SEPOLIA_RPC_URL"
```

</AnchoredAccordion>

<AnchoredAccordion title="Step 9: Confirm your token now routes through v2 pools" number={9} depth={3}>

Re-run the Step 1 checks. You should now see the v2 pool addresses as the live `tokenPool` on both chains, and
`typeAndVersion` should report v2.

1. Ethereum Sepolia:

```bash filename="Terminal"
npx hardhat getTokenConfig --tokenaddress $ETHEREUM_SEPOLIA_TOKEN --network sepolia
npx hardhat getTypeAndVersion --address $ETHEREUM_SEPOLIA_V2_POOL --network sepolia
```

Your output should look something like this:

```bash filename="Terminal"
Token Config:
  tokenPool:            0xNewSepoliaV2PoolAddress

typeAndVersion: BurnMintTokenPool 2.0.0
```

2. Arbitrum Sepolia:

```bash filename="Terminal"
npx hardhat getTokenConfig --tokenaddress $ARBITRUM_SEPOLIA_TOKEN --network arbitrumSepolia
npx hardhat getTypeAndVersion --address $ARBITRUM_SEPOLIA_V2_POOL --network arbitrumSepolia
```

Your output should look something like this:

```bash filename="Terminal"
Token Config:
  tokenPool:            0xNewArbitrumV2PoolAddress

typeAndVersion: BurnMintTokenPool 2.0.0
```

</AnchoredAccordion>

<AnchoredAccordion title="Step 10: Safety checks and cleanup (after v1 inflight settles)" number={10} depth={3}>

After cutover, keep the v1 remote pool addresses configured on the v2 pools until you are confident there are no more
in-flight v1 messages. There is no cost to waiting longer.

Once you're ready, remove the old v1 remote pool
addresses from the v2 pools.

<GitHubCard
  title="removeRemotePool.ts"
  href="https://github.com/smartcontractkit/docs-cct-hardhat/blob/main/tasks/configure/remote-pools/removeRemotePool.ts"
  iconName="github-svg-card"
>
  View the remote pool removal task on GitHub.
</GitHubCard>

1. On the Sepolia v2 pool, remove the old Arbitrum v1 pool address:

```bash filename="Terminal"
npx hardhat removeRemotePool \
  --tokenpool $ETHEREUM_SEPOLIA_V2_POOL \
  --destchain arbitrumSepolia \
  --remotepooladdress $ARBITRUM_SEPOLIA_V1_POOL \
  --network sepolia
```

Your output should look something like this:

```bash filename="Terminal"
➖ Remove Remote Pool

⚠️  WARNING: All inflight transactions from this pool will be rejected after removal.

Current Remote Pools: 2
  [0] 0xOldArbitrumV1PoolAddress
  [1] 0xNewArbitrumV2PoolAddress

✅ Remote pool removed successfully!
```

2. On the Arbitrum v2 pool, remove the old Sepolia v1 pool address:

```bash filename="Terminal"
npx hardhat removeRemotePool \
  --tokenpool $ARBITRUM_SEPOLIA_V2_POOL \
  --destchain sepolia \
  --remotepooladdress $ETHEREUM_SEPOLIA_V1_POOL \
  --network arbitrumSepolia
```

<Aside type="caution" title="If you removed too early">
  If a v1-sent message is still in-flight and you removed its source pool address, it can fail validation on the
  destination. You can recover by adding the pool address back with <code>addRemotePool</code>, then retry cleanup
  later.
</Aside>

<GitHubCard
  title="addRemotePool.ts"
  href="https://github.com/smartcontractkit/docs-cct-hardhat/blob/main/tasks/configure/remote-pools/addRemotePool.ts"
  iconName="github-svg-card"
>
  View the remote pool add task on GitHub (recovery).
</GitHubCard>

Recovery example (re-add the old pool address, then retry cleanup later):

```bash filename="Terminal"
npx hardhat addRemotePool \
  --tokenpool $ETHEREUM_SEPOLIA_V2_POOL \
  --destchain arbitrumSepolia \
  --remotepooladdress $ARBITRUM_SEPOLIA_V1_POOL \
  --network sepolia
```

<Aside type="note" title="Optional hardening">
  After migration and cleanup, you can also revoke mint/burn roles from the old v1 pools (if your token's access control
  allows it). This is token-specific and may require calling role revocation functions directly on your token contract.
</Aside>

</AnchoredAccordion>
