In addition to Chainlink's standard liquidity-weighted crypto price streams, Data Streams offers two exchange-sourced stream types for perpetual futures markets: **Top-of-Book** and **Perpetual Mark Price**. Both are sourced directly from a single centralized exchange's public market data feeds, rather than aggregated across venues.

## Top-of-Book

Top-of-Book streams report the best bid and best ask currently resting on a specific exchange's order book for a given instrument. These streams are useful for protocols that need to reflect a specific venue's live order book conditions, such as perpetual futures for tokenized equities and commodities (RWA perps) traded on Binance and Hyperliquid.

<Aside type="note" title="Single-source data">
  Top-of-Book streams are sourced from a single exchange's order book, not a liquidity-weighted composite across
  venues. There is no redundant cross-validation between exchanges for a given Top-of-Book feed.
</Aside>

### Data sources

| Exchange       | Public channel                                              | Fields consumed                              |
| -------------- | ------------------------------------------------------------ | --------------------------------------------- |
| Binance        | `<symbol>@bookTicker` (Individual Symbol Book Ticker Stream) | `b` (best bid price), `a` (best ask price)     |
| Hyperliquid     | `l2Book`                                                     | Best bid/ask `px` from `levels[0]`/`levels[1]` |

Additional exchanges may be added over time as new streams are onboarded.

### Schema

Top-of-Book streams use the [RWA Advanced (v11) schema](/data-streams/reference/report-schema-v11):

| Schema field | Populated from                                          |
| ------------ | -------------------------------------------------------- |
| `bid`        | Exchange's best bid price                                 |
| `bidVolume`  | Size at the best bid, when provided by the exchange       |
| `ask`        | Exchange's best ask price                                 |
| `askVolume`  | Size at the best ask, when provided by the exchange       |
| `mid`        | Calculated by the Chainlink DON — **not** provided by the exchange |
| `marketStatus` | Reflects the venue's availability. Crypto perpetual markets generally trade continuously; see [Market Status Values](/data-streams/reference/report-schema-v11#market-status-values) for how this maps for a specific feed. |

<Aside type="caution" title="Mid price is calculated, not sourced">
  `mid` is calculated by the Chainlink DON from the reported bid and ask. It is not a field provided directly by the
  underlying exchange.
</Aside>

## Perpetual Mark Price

Perpetual Mark Price streams report the mark price (and, where available, the index price) that an exchange uses internally for a perpetual futures contract — the reference price used for funding rate calculations and liquidation triggers on that venue.

### Data sources

| Exchange    | Public channel                                    | Mark price field                                 |
| ----------- | -------------------------------------------------- | -------------------------------------------------- |
| Binance     | `<symbol>@markPrice` (Mark Price Stream)           | `p` (mark price)                                   |
| Hyperliquid | `activeAssetCtx`                                   | `ctx.markPx`                                       |

### Schema

Perpetual Mark Price streams use the [Crypto Advanced (v3) schema](/data-streams/reference/report-schema-v3). The exchange's reported mark price populates the `price` field.

## Data freshness and update frequency

Both stream types are **event-driven**: a new observation is only published when the underlying exchange emits a new datapoint on its public channel. There is no fixed polling interval.

Expected end-to-end latency from the underlying exchange to node operators is approximately 500ms. This is a typical figure, not a guaranteed performance bound, and can vary based on network conditions and exchange-side publishing behavior.

## Risk considerations

- **Single-source dependency**: Each Top-of-Book or Mark Price feed is sourced from one exchange. If that exchange stops publishing updates, there is no automatic fallback to another venue for that feed.
- **Venue-specific pricing**: Top-of-Book and Mark Price reflect one exchange's order book or internal mark price calculation, which can diverge from prices on other venues, especially during periods of low liquidity or high volatility on the source exchange.
- **Review [Developer Responsibilities](/data-streams/developer-responsibilities)** before integrating either stream type into a production application.
