## CCIPLocalSimulatorFork

A contract that simulates CCIP (Cross-Chain Interoperability Protocol) message routing in a Foundry test environment, for every CCIP era: pre-1.6 (`EVM2EVMOnRamp`), 1.6 and CCIP 2.0 (CCV-based lanes, which live testnet lanes run today).

[`CCIPLocalSimulatorFork`](https://github.com/smartcontractkit/chainlink-local/blob/v0.3.1/src/ccip/CCIPLocalSimulatorFork.sol)

<Aside>
This contract provides utilities for testing cross-chain message routing by simulating message sending and receiving between different blockchain networks in a Foundry test environment. Works with Foundry only. Fork tests need `evm_version = "cancun"` or later (deployed CCIP 2.0 contracts use Cancun opcodes) and Foundry >= 1.5.1.
</Aside>

## Enums

### CCIPEra

```solidity
enum CCIPEra { UNKNOWN, PRE_V1_DOT_6, V1_DOT_6, V2 }
```

<Aside>The CCIP protocol version of a lane, detected from the OnRamp's `typeAndVersion()`.</Aside>

### V2VerificationMode

```solidity
enum V2VerificationMode { STRICT, HYBRID, SYNTHETIC_ONLY, OFFRAMP_DERIVED }
```

<Aside>
  How CCIP 2.0 messages are verified when routed. The default is `OFFRAMP_DERIVED`: the CCV selection is derived from
  the destination OffRamp's `getCCVsForMessage(encodedMessage)` and the raw encoded message is executed through the
  permissionless `execute` entrypoint, so routing does not depend on the local `MessageV1` codec. CCV attestations are
  simulated with a synthetic no-op verifier.
</Aside>

### V2ExecutionMode

```solidity
enum V2ExecutionMode { AUTO, RESPECT_NO_EXEC, MANUAL_ONLY }
```

<Aside>
  How `NO_EXECUTION_ADDRESS` (manual execution) messages are handled. The default is `RESPECT_NO_EXEC`: they are queued
  for `executePendingV2Message` instead of executed.
</Aside>

### MessageStatus

```solidity
enum MessageStatus { NOT_FOUND, QUEUED, FAILED, SUCCESS }
```

<Aside>
  Outcome of a captured CCIP message (see `getMessageStatus`). `NOT_FOUND`: never captured by this simulator. `QUEUED`:
  a CCIP 2.0 `NO_EXECUTION_ADDRESS` message waiting for `executePendingV2Message`, or a 1.6 / 2.0 message whose
  destination fork was not passed to `switchChainAndRouteMessage` yet (a later call that includes it routes the
  message). `FAILED`: not routed, or execution did not succeed (the reason is recorded).
</Aside>

## Functions

### constructor

Initializes the contract and sets up logging and persistence.

```solidity
constructor()
```

<Aside>
Initializes the contract by:

- Starting log recording (`vm.recordLogs`)
- Placing the Register and its `RegisterData` shards with `vm.etch` at deterministic addresses, and making them persistent
- Setting the default `V2VerificationMode` to `OFFRAMP_DERIVED`, strict routing to enabled, and `V2ExecutionMode` to `RESPECT_NO_EXEC`
- Pre-registering the verified CCIP 2.0 routers for Ethereum Sepolia (`0x784d49a71BB4C48eB7dA4cD7e6Ecb424f9b5EAB1`) and Avalanche Fuji (`0x7C9B8B4e8024e5Ee8A630F6FCe9015e470dA5763`)

</Aside>

### switchChainAndRouteMessage

Routes a cross-chain message on the destination network after switching to the specified fork.

```solidity
function switchChainAndRouteMessage(uint256 forkId) external
```

<Aside>
To be called after sending a cross-chain message (`ccipSend`). The function:

- Searches past logs for the supported CCIP send events (all eras)
- Switches to the destination network fork
- Routes the sent message on the destination network
- If you sent more than one message, it tries to route all of them to `forkId`. A 1.6 or 2.0 message to another chain is kept (status `QUEUED`) and routed by a later call that includes its destination fork.

`forkId` is the active fork when the call returns.

</Aside>

#### Parameters

| Parameter | Type      | Description                                                                                 |
| --------- | --------- | ------------------------------------------------------------------------------------------- |
| forkId    | `uint256` | The ID of the destination network fork (returned by `createFork()` or `createSelectFork()`) |

<Aside type="caution">

**Possible Reverts**

With strict routing enabled (the default), reverts with `CCIPLocalSimulatorFork__MessageNotRouted(messageId, reason)` when a captured message cannot be routed to any of the given forks, and with `CCIPLocalSimulatorFork__MessageExecutionFailed(messageId, reason)` when a routed message does not execute successfully. Call `setStrictRouting(false)` to record failures instead and read them with `getMessageStatus`.

</Aside>

### switchChainAndRouteMessage (multiple forks)

Override variant of `switchChainAndRouteMessage(uint256 forkId)` for multiple destination forks.

```solidity
function switchChainAndRouteMessage(uint256[] memory forkIds) external
```

<Aside>
  Goes through the provided `forkIds` and routes messages to the matching destination. A 1.6 or 2.0 message to a chain
  that is not in `forkIds` is kept (status `QUEUED`) for a later call. With several destinations, either pass every
  destination fork at once with this overload, or call `switchChainAndRouteMessage` once per destination fork.
</Aside>

#### Parameters

| Parameter | Type        | Description                              |
| --------- | ----------- | ---------------------------------------- |
| forkIds   | `uint256[]` | The IDs of the destination network forks |

### setLaneDefaultCCVs

Points a destination lane's default CCVs at a CCV address by impersonating the OffRamp owner.

```solidity
function setLaneDefaultCCVs(uint256 forkId, address offRamp, uint64 sourceChainSelector, address ccv) external
```

<Aside>
  Fork-only testing helper for CCIP 2.0 lanes: the mocked CCV must be configured on the destination lane before a
  captured message can be routed through the permissionless execution path. Router, enabled flag, OnRamp bindings and
  lane-mandated CCVs are preserved, so the fork lane is never less strict than production.
</Aside>

#### Parameters

| ccv                 | `address` | The CCV address to set as the lane default         |

### setStrictRouting

Enables or disables strict routing (enabled by default).

```solidity
function setStrictRouting(bool strict) external
```

<Aside>
  When enabled, `switchChainAndRouteMessage` and `executePendingV2Message` revert with
  `CCIPLocalSimulatorFork__MessageNotRouted` when a captured CCIP message cannot be routed to any of the given forks,
  and with `CCIPLocalSimulatorFork__MessageExecutionFailed` when a routed message does not execute successfully. When
  disabled, failures are logged and recorded (see `getMessageStatus`) and routing continues.
</Aside>

#### Parameters

| Parameter | Type   | Description                                                |
| --------- | ------ | ---------------------------------------------------------- |
| strict    | `bool` | Whether to enable (true) or disable (false) strict routing |

### executePendingV2Message

Executes a pending CCIP 2.0 `NO_EXECUTION_ADDRESS` message on the current fork.

```solidity
function executePendingV2Message(bytes32 messageId) external returns (bool attempted)
```

<Aside>
  Routes the pending message through the destination OffRamp's permissionless `execute` entrypoint. Returns `false` (and
  records a `FAILED` outcome) when no OffRamp on the current fork serves the message's lane. The message is dequeued
  once processed.
</Aside>

#### Parameters

| Parameter | Type      | Description                    |
| --------- | --------- | ------------------------------ |
| messageId | `bytes32` | The CCIP message ID to execute |

#### Returns

| Parameter | Type   | Description                                            |
| --------- | ------ | ------------------------------------------------------ |
| attempted | `bool` | Whether an execution was attempted on the current fork |
