<Aside type="note" title="CCIP 2.0 supports Faster-Than-Finality (FTF)">
  <ol>
    <li>
      Chainlink CCIP 2.0 supports [Faster-Than-Finality (FTF)](/ccip/concepts/execution-latency/ftf), which lets
      supported lanes process messages with a requested finality mode instead of always waiting for full finality.
    </li>
    <li>In these tutorials, the scripts encode the requested mode into V3 `extraArgs` as `requestedFinalityConfig`.</li>
    <li>
      Supplying extraArgs that were encoded off-chain keeps the smart contract compatible with future CCIP versions
      without requiring an upgrade. We recommend against hardcoding extraArgs inside a smart contract.
    </li>
    <li>
      We demonstrate FTF with a numeric block depth of `32` (`BLOCK_DEPTH=32`) in this tutorial; omit `BLOCK_DEPTH` (or
      set it to `0`/`DEFAULT`) to request `finalized` finality (`WAIT_FOR_FINALITY_FLAG`), which is the default.
    </li>
  </ol>
</Aside>
